# Documentation assistant evaluation

The baseline does **not** meet the release criteria: 6 of 12 answers pass, 2 are
partial and 4 fail. In particular, the assistant invents `cols` as an argument to
`facet_wrap()`, and three generated examples fail in fresh R processes.

## Method

Sent three initial checks, reviewed their answers and then sent nine additional
cases to the public chat endpoint. The model was
`@cf/meta/llama-3.3-70b-instruct-fp8-fast`. Requests disabled similarity caching
and query rewriting, matching the widget's current rewriting setting. Generation
was limited to 1,200 output tokens; all responses finished normally (`stop`).
The follow-up included the previous user question and complete assistant answer.

Raw responses include retrieved chunks, model usage and timing. They are in
`2026-10-23T15-42-17.561Z/` (initial checks) and
`2026-10-23T15-43-08.126Z/` (remaining cases). The runtime configuration was not
changed during the evaluation.

Reviewed the generated R blocks before executing them. Ran seven examples in
separate R processes, loading the local package with `devtools::load_all()`.
Plotting checks built the ggplot object; mutation and filtering checks asserted
the resulting class, size and values. The two conversation examples received a
small three-layer `temp` fixture because their questions assume that object
already exists. Standalone examples received no missing library imports or
syntax corrections.

Environment: R 4.6.1, tidyterra 1.3.0.9000, terra 1.9.50 and ggplot2 4.0.3.
The indexed documentation is the published release; successful local execution
does not establish compatibility with every older dependency version.

not answer the requested scale question. Complete process output is saved in

## Availability, sources and usage

All 12 requests returned HTTP 200. These successful statuses do not imply
correct answers. The API reported 53,101 total tokens and 1,919.14 neurons across
the 12 requests. This is usage for these requests, not the account's remaining
quota or a monetary estimate.

Median response time was 11.29 seconds, with a range of 5.15–17.16 seconds.
Total measured request time was 126.68 seconds. These are non-streaming request
times and do not measure the widget's time to first token.

All cited tidyterra and ggplot2 documentation URLs returned HTTP 200. Two
Stack Overflow links in the unsupported-function answer returned HTTP 403 to the
automated HEAD check; this does not establish that those links are broken for a
browser. Source relevance was reviewed separately: a working citation does not
validate the fabricated constructor, the `cols` argument or the wrong scale.
Detailed checks and usage totals are in `summary.json`.

## Next changes to evaluate

1. Require standalone snippets to load their dependencies and prefer documented
   dataset examples over constructing unsupported terra calls.
2. Improve conversation retrieval. With rewriting disabled, the second question
   retrieved pivoting and reshaping material instead of the documented facet
   example. Evaluate history-aware rewriting against the same failing case.
3. Strengthen exact API grounding: retain function families and argument names,
   read defaults from usage blocks and distinguish `maxcell` from CRS-related
   reprojection. Cases 07 and 08 already retrieved useful evidence, so changing
   retrieval alone will not address every failure.
4. After a targeted change, rerun the failed and partial cases plus one passing
   raster example and one unsupported-function refusal. Preserve this baseline.

The remaining live-site check belongs after deployment: the PR was still open
when this baseline ran. No generation settings, indexing resources or public
site deployment were changed by these tests.
